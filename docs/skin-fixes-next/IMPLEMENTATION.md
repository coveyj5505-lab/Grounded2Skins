# Reviewed skin fixes and isolated runtime candidates

This iteration starts from the current UE5.7.4 packages, preserving each mesh's own reference/material prefix and112-byte native suffix. It does not transplant memory offsets from the older SDK. Body/backpack readbacks are checked independently because their reference payloads can differ. Textures, private material paths, auxiliary hair/helper meshes and all other unrelated chunks remain byte-exact.

The visual review deliberately rejected two kinds of technically valid output: remaining upper-cape holes and a twisted/open copied forearm. It also rejected a wrong-colored replacement forearm texel. The final cape includes a small chest-weighted rear underlay beneath the original collar; the hand uses a verified existing palm texel matching both the original source image and decoded native atlas. The hand remains a stylized flat proxy, not a newly animated finger rig.

Source authoring scripts are in pipeline/skin-fixes. The input Blender files and preserved originals remain in the existing private workspace. Current isolated authoring/native builds live at /workspace/mod-work/skin-fixes-next, backed by /tmp/grounded2-skin-fixes-next because the main workspace filled; released/source backups were not removed. Candidate Blends and native intermediates are retained there. New public ZIPs use distinct names and require the old replacement trios to be moved outside Paks, avoiding ambiguous overriding packages.

The crook runtime only changes its exact container revision gate and FP side placement. Component lifetime, hand-slot checks, retained FP/TP components and collision-off behavior remain the confirmed implementation. During native punches the copied resting hand is omitted to avoid duplicate limbs. The accessory still performs its existing cosmetic hook-forward movement, not the native spear animation. That limitation is explicit.

The flight repair adds direct Character.Mesh discovery, which was absent in the adapter that logged WAIT: Buzz/Max source mesh. Source identities are logged once; owned-component enumeration remains a supplement. Mocked regressions demonstrate the missing-list-body case and deduplication. The current UE5.7 flight mesh position/index/UV bytes exactly match the already-corrected, personally reviewed side-socket flight asset.

Tuft suppression is a bounded optional stage. SDK declarations establish InventoryComponent.UsingGliderItem, Item.GetItemVisuals, EquipmentComponent.GetItemInSlot and the Glider enum name. Their actual availability/semantics in this build still require Windows confirmation. All lookups are reflected live; no offsets are copied. Only the resolved item's own PrimitiveComponent visibility is changed, captured/restored by the same flight transaction. No RPC, equipment mutation, item consumption, collision or movement operation is used. A failed tuft lookup leaves that visual alone while flight proceeds. FP restores native presentation; multiplayer visuals remain local-client only.

Native spear substitution remains blocked on the actual animation dependencies and notification/root-motion/slot inspection. The prepared collector reads only the known recorded montage and its actual indexed animation/skeleton imports, bounded to32 packages/64MiB. It does not request another gameplay probe. Direct gameplay montage substitution could change socket traces/timing; that would violate the cosmetic requirement even if damage numbers were unchanged.

See visual-review.json and individual native-validation JSONs for evidence; downloads.json records exact archive and member hashes. Windows acceptance remains necessary.
